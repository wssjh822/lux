Lux

一门用 C++ 写成的静态类型编程语言，编译为原生可执行文件
语法现代，运行速度与手写 C 同速；也可用 原生后端 零依赖直出 ELF

$ luxc hello.lux --run
v0.7.0 静态类型 C 后端（C17） 原生后端（--native） struct 结构体 数组 + 切片 模块系统 + 标准库 REPL MIT

01它长什么样

现代静态风格：fn 定义函数、let 声明变量、类型写在名字后面。

// hello.lux
fn fib(n: int) -> int {
    if n < 2 {
        return n;
    }
    return fib(n - 1) + fib(n - 2);
}

fn main() {
    let name = "Lux";          // 类型推断 → string
    println("你好, " + name + "!");

    for i in 0..10 {
        print(fib(i));
        print(" ");
    }
    println("");
}
# 编译成可执行文件
$ luxc hello.lux
$ ./hello

03设计取舍

每一条都指向同一个目标：既要写起来舒服，又不能为舒服付出运行时的代价。

◎

零成本抽象

int 就是 int64_t，string 就是 const char*。没有装箱、没有运行时类型标签、没有 GC 暂停。

◇

只有一条隐式转换

仅允许 int → float 这种不会丢信息的提升。"答案是 " + 42 会编译失败，你必须写 string(42)。

▲

条件必须是 bool

不做 C 那种"非零即真"的隐式转换。if 1 { } 是错误，挡掉一整类常见 bug。

◆

除零是运行时错误

整数除法走带检查的 lx_idiv()，除零时打印清晰的错误信息，而不是 SIGFPE 崩溃。

✦

诊断指回源文件

生成的 C 里插入 #line 指令，C 编译器的警告和运行时断言都能指回 .lux 的行号。

❖

生成的代码零警告

所有示例生成的 C 在 -Wall -Wextra 下都是 0 警告 —— 中间产物也是干净的。

▦

数组，引用语义 0.5 新增

let a: int[] = [1,2,3]，越界立即 panic，push / pop / insert / remove 自动扩容；传参与赋值共享同一数组，和 Python list 一致。

↻

for-in 迭代 0.5 新增

for x in arr 逐元素、for c in s 逐字符；配合 split / chars / join，文本处理一行搞定。

❏

struct 结构体 0.7 新增

struct Point { let x: int; }，构造 Point { x: 1 }，成员读写 p.x += 1，支持嵌套与 struct 数组，双后端行为一致。

◈

if 表达式 0.7 新增

let x = if c { a } else { b }; —— 分支各是一个表达式，int / float 混合自动提升。

▸

命令行参数 0.7 新增

fn main(argv: string[]) 直接拿到参数数组，argv[0] 为程序名；C 后端与原生后端约定一致。

✳

原始字符串 / nan · inf 0.7 新增

r"no\escape" 不做任何转义；nan / inf 作为浮点字面量，与 isnan / isinf 配合。

⟲

通用左值复合赋值 0.7 新增

a[i] += v、grid[i][j] = v、p.x *= 2、arr[i].x += 1；左值子表达式只求值一次。

⌘

原生代码生成后端 0.6 新增

luxc --native 直出本机架构（x86-64 / aarch64）Linux ELF，不调用 C 编译器、不链接 libc；运行时全部由 Lux 自身实现。

05性能

同一套试除法素数算法，统计 2..2,000,000 之间的素数（正确结果 148,933），各跑 3 次取最快。括号内为相对手写 C 的倍数。

手写 C gcc -O2（基准 1.00×）
1.00×
Lux C 后端 luxc -O2 → gcc -O2
1.01×
Lux 原生后端 luxc --native（未优化直出）
2.05×
Python 3 解释执行
9.7×

Lux 生成的代码与手写 C 同速（1.01×）； 原生后端不依赖 C 编译器、不做优化，约 2 倍 于 手写 C，仍远快于解释执行（Python 的 9.7× 与本机原生 2.05× 同量级基准）。 两套独立后端在回归里做逐字节差分对拍，互相校验正确性。

06已知限制与下一步

以下取舍是刻意为之 —— 把不确定的东西留在后面，先把确定的部分做对。

当前限制（0.7）

  • 不会自动释放内存 —— 字符串拼接、数组扩容、struct 构造都会持续占用；ARC 是 0.7.x / 0.8 的主题（设计草案见 docs/arc.md）
  • 数组与 struct 都是引用语义，不支持 == 比较（请逐个比较元素 / 字段）
  • len() / find / substr / chars / 字符串 for-in 按 UTF-8 字节计，不是字符数
  • 空数组 [] 作为函数实参无法推断元素类型（请先声明带类型的变量）
  • 原生后端在溢出 / 下溢 / 极端指数附近的浮点数学与 libm 有末位差异（常规范围精度良好）
  • 标识符只支持 ASCII；C 后端需系统装有 C 编译器（原生后端不需要）
  • 只支持 POSIX 平台（Linux / macOS），Windows 请用 WSL / MSYS2
