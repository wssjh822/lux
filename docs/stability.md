# Lux 稳定性说明（面向 1.0）

本文档说明 Lux 在 1.0 冻结时**承诺稳定**的接口，以及**明确不包含**的内容。
0.9.4 是 **ARC 收官版**：原生后端 free list 落地、ARC 双后端完整且默认开启
（新增 `--no-arc`），`T?` 装箱回收闭环，并新增错误消息通道
`last_error()` 与 `find_opt()` 可选变体 —— 未引入任何新语法。
1.0 之后，任何签名或诊断文案的改动都视为破坏性变更。

## 1. 稳定承诺（1.0 冻结）

| 范畴 | 承诺 |
| --- | --- |
| 语法 | 本文档所述的全部关键字、字面量、运算符、语句与表达式形态 |
| 类型 | `int`（64 位有符号）、`float`（IEEE-754 double）、`bool`、`string`（UTF-8）、数组 `T[]`、struct、可选类型 `T?`（0.8）、`void` |
| 语义 | 数组 / struct 的**引用语义**、切片**复制语义**、`int→float` 与 `T→T?` 是仅有的隐式转换、`len()` 返回**字节数** |
| 错误通道 | `T?` / `?` 传播 / `or` 兜底（按左操作数类型分派）/ `name!` panic 变体；`int` / `float` / `read` 的失败返回 `none` |
| 运行时错误 | 越界 / 除零 / 断言等 panic 的**文案格式**（见第 3 节） |
| 诊断 | 错误码（`E0001`…/`W1001`…）与 `file:line:col` 定位格式 |
| 标准库 | `math` / `time` / `system` / `file` / `string` 已列出的函数签名与行为；`find_opt(s, sub): int?`（0.9.4） |
| 错误消息 | `last_error(): string` —— 最近一次标准库失败的说明（0.9.4，无 import 即可用） |
| 内存 | 引用计数（ARC）默认开启；`--no-arc` 退回只增不减语义（0.9.4） |
| 命令行 | `luxc` 的既有选项（`-o` / `--run` / `--emit-c` / `--native` / `--arc` / `--no-arc` / `-O` …）与子命令 `build` / `repl` / 包管理 |

## 2. 命名审查结论（D1）

0.7 完成了标准库命名审查，规则如下（写进 grammar.md 与 README）：

1. **裸函数**用于与接收者无关的操作：`len(x)`、`abs(x)`、`split(s, sep)`、
   `format(fmt, ...)`、`sqrt(x)`、`now()`。
2. **方法**只用于「必然作用于某个数组变量且带副作用」的操作：
   `a.push(v)` / `a.pop()` / `a.insert(i, v)` / `a.remove(i)` / `a.clear()`。
   规则：如果操作会改变接收者，且接收者必须是可寻址变量，就用方法。
3. **模块限定**用于可能撞名的通用名：`math.pow`、`time.now` 等都可裸用
   （默认 import），别名导入时用 `别名.成员`。
4. `now()`（墙钟，可回退）与 `monotonic()`（单调，测耗时）**不合并**：
   语义不同，合并会掩盖时钟回拨问题。
5. `print` / `println` 是输出；`format` 返回字符串，不输出。
6. **panic 变体（0.8）**：可能失败的内建用 `name!` 后缀表示“失败即 panic”
   （`int!` / `float!` / `read!`），不带后缀的 `name` 返回 `T?`。`!` 后缀
   与一元逻辑非不冲突（前者只出现在 `IDENT ! (` 位置）。
7. **`or` 分派（0.8）**：`or` 关键字按左操作数类型分派（`bool` → 逻辑或，
   `T?` → 兜底）；`||` 永远是逻辑或，不参与分派。

## 3. 运行时错误文案（冻结）

所有 panic 统一写成：

```
lux: 运行时错误: <说明>
lux: （如果是递归函数，也可能是调用层数过深导致栈溢出）
```

常见 `<说明>`：

| 场景 | 文案模板 |
| --- | --- |
| 数组下标 | `数组下标越界：下标 %lld，但长度只有 %lld（下标从 0 开始）` |
| 字符串下标 | `字符串下标越界：下标 %lld，但长度只有 %lld（下标从 0 开始）` |
| 切片范围 | `切片范围越界：起点 %lld，终点 %lld，长度 %lld` |
| 整数除零 | `整数除法的除数为 0` |
| 整数溢出除法 | `整数除法结果溢出` |
| 取模除零 | `取模运算的除数为 0` |
| 空数组 pop | `对空数组调用 pop()` |
| 断言 | `assert 失败：<消息>（第 %d 行）` |
| 可选解包 | `<what> 失败：值为 none`（`int!` / `float!` / 用户 `f!`） |
| 文件读取 | `文件读取 失败：无法读取 '<路径>'`（`read!`，0.9 起把路径写进 panic） |

C 后端与原生后端必须逐字一致（回归测试以逐行 diff 校验）。

## 4. 1.0 不包含（明确砍掉）

- **高阶函数 / `fn` 类型**：`fn(T,...) -> R` 类型与 `sort` / `map` / `filter`
  未实装；**明确不进 1.0**（见 §6.2），1.x 首项。
- **`static let` 全局可变变量**：只支持顶层 `const`（编译期常量）。需要跨函数
  共享可变状态请用数组（引用语义）或把它作为参数传递。
- **`--emit-c` 的完全可移植性**：生成的 C 仍使用 GCC 语句表达式（数组字面量
  的临时）与 `__attribute__((cleanup))`（ARC 模式），暂不保证能在
  非 GCC/Clang 编译器上编译。
- **泛型**：`sort` 等先用 `fn` 类型 + 手工实例化顶着，见路线图。
- **`map<K,V>`**：需要新的运行时表示与打印器，放到 1.x。
- **无符号整数**：只有有符号 64 位 `int`。
- **并发**：不引入线程 / goroutine；ARC 与并发不同时上。
- **Windows**：POSIX-only（Linux / macOS）；不提供半吊子移植。
- **LLVM 后端**：C 后端与自研原生后端两条路径足够。

## 5. 破坏性变更窗口

| 版本 | 允许的破坏性变更 |
| --- | --- |
| 0.7.x | ARC 表示层、panic 文案微调 |
| 0.8.0 | 错误通道语义迁移（`int("abc")` 不再静默 0、`read()` 不再 panic）、标准库签名收尾 |
| 0.9.0 | struct 返回落穿升级为硬错误 `E0005`；panic 文案补全（切片带数字、`assert` 进 `lx_panic`、`read!` 带路径）；`T?` 不能作数组元素 / struct 字段（与 grammar 一致）；新增在线包管理（`install` / `search` / `upgrade` / `publish`） |
| 0.9.1 | 注册表上传 / 修改 / 删除要求账号（`luxc login` / `unpublish`），服务端网页界面由 `index.php` 提供 |
| 0.9.2 | **ARC 表示层落地**（堆对象加引用计数头、字符串字面量改为静态不可变对象、

| 0.9.3 | 新增 `luxc build`（LuxBuildFile）、`from … import …`、`#import` 与
`#define`/`#ifdef` 等预处理指令（均为纯新增，不破坏既有语法）；修复 ARC

| 0.9.4 | **无新语法**：ARC 默认开启（新增 `--no-arc` 逃生阀）、原生后端

| 1.0.0 | **无**；只冻结（`fn` 类型 / `map` 等进入 1.x） |

## 6. 0.9.2 拍板记录（不再骑墙）

### 6.1 ARC → 进 1.0，0.9.4 转正（已兑现）

- **决定**：ARC 进 1.0。0.9.2 先落地**表示层**（每个堆对象前 16 字节：
  `refs` + `on_zero`；字符串字面量是 `refs = -1` 的静态不可变对象）
  与 **C 后端**的引用计数（`--arc` 开启）。
- **extern 约定**：extern fn 的 `string` 参数与返回值都是**借用视图**
  （`const char*` 不变），ARC 只管 Lux 自己分配的对象；extern 返回值不参与回收。
- **0.9.2 的 ARC 覆盖**：局部变量（`let` / `for` 绑定）、赋值（含 `x = x + …`、
  `x += …`）、函数返回、数组 `push/pop/insert/remove/set/clear/slice`、
  struct 字段与嵌套、嵌套字符串拼接（`a + b + c` 的中间串不再泄露）。
- **0.9.2 的已知缺口**（0.9.3 补精度、0.9.4 补回收）：`T?` 装箱不回收；
  控制流条件里的临时串会漏；原生后端仍是 bump。
- **默认**：0.9.2 里 `--arc` 是可选项，不带时行为与 0.9.1 完全一致
  （`lx_gc_enabled = 0`）。
- **0.9.4 已兑现**（本节承诺全部关闭）：C 后端 ARC 默认开启；原生后端
  按 §2.3 实现尺寸分级 free list 并插入引用计数，`--arc --native` 解禁；
  ARC 场景进入双后端逐字节差分矩阵；`T?` 装箱槽不再只增不减。
  新增 `--no-arc` 作为逃生阀（退回 0.9.1 的只增不减语义，仅供排查 / 对拍）。
- **0.9.4 仍存的最小缺口**（只造成泄漏，不造成误释放，见
  [`arc.md`](arc.md) §2.4）：`main(argv)` 的 argv 数组是一次性泄漏；
  原生后端在 `break` / `continue` / `return` 提前离开块时不释放该块
  已声明的引用型局部。

### 6.2 `fn` 类型 → 不进 1.0

- `fn(T,…) -> R`、`sort` / `map` / `filter` 不在 1.0；进入 1.x。
- 原因：要绕开「`T?` 不能作数组元素」这个交叉点，`map` 需要额外设计
  （例如提供 `map_opt`），在 1.0 冻结前不引入不确定的签名。

### 6.3 deps 语义 → 安装级解析，无 semver 求解

- `luxc install` / `upgrade` 确实**递归安装 `deps`**（pkgs.cpp 实现），
  版本约束只做 `^ ~ >= <= =` 的简单匹配，不做满足性求解；
  存在环时以“已访问集合”终止。
- 因此 stability 不再写“不做依赖解析”，改成本节的准确描述。
